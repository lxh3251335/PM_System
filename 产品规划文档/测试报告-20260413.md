## 二、新发现的 Bug（需关注）

### [P1-1] 项目复制丢失 cabinet_id 和 meter_area

**位置**：`backend/app/api/projects.py:541-559`（`copy_project` 函数）

**问题**：`Device` 新增字段 `cabinet_id`（所属电控柜）和 `meter_area`（电表区域）在复制时未被拷贝。

**影响**：
- 复制后的项目，电控柜下的子设备失去与柜体的关联
- 电表的"冷链/空调/照明"等区域属性全部丢失
- 设备登记页面显示会错乱

**修复建议**：在 copy_project 的 Device 构造中补充：
```python
cabinet_id=cabinet_id_map.get(old_dev.cabinet_id) if old_dev.cabinet_id else None,
meter_area=old_dev.meter_area,
```

需要注意 cabinet_id 需用 **新旧设备 ID 映射** 转换（并且 cabinet 设备要先复制完再复制其子设备），否则会指向旧项目。

### [P1-2] 通讯拓扑"修改/移除"在 API 失败时仍显示成功

**位置**：`demo/project-detail.html:1232-1260`（`editCommTopoItem`）、`1268-1288`（`unassignCommTopoItem`）

**问题**：
```js
try {
    await api.devices.updateDevice(deviceId, { ... });
} catch (err) {
    console.warn('...', err.message);  // 静默吞错
}
// 继续更新 localStorage 和 UI，最后弹成功提示
api.projects.showSuccess('通讯配置已更新');
```
当网络异常或后端返回错误时，用户仍看到绿色"已更新"提示，但刷新后复原，造成**跨设备不同步**和**信任危机**。这与今天刚修复的"设备数据同步"属于同类问题。

**修复建议**：catch 分支应 `api.projects.showError` 并 `return`，不落本地。

---

### [P1-3] `editCommTopoItem` 输入无效 COM 口时静默清空端口

**位置**：`demo/project-detail.html:1224-1235`

**问题**：
```js
var newPort = prompt('请输入 COM 口...', curPort || '');
// ...
newPort = String(newPort).trim().toUpperCase();
var portNum = null;
var m = /^COM(\d+)$/i.exec(newPort);
if (m) portNum = parseInt(m[1]);
// 后续直接：gateway_port: portNum（即 null）
```

用户误输入 `"com3"` 以外的任何值（例如 `"1"`、`"COM 3"`、空格），`portNum` 保持 `null`，后端把 `gateway_port` 清空，但 UI 仍显示"已更新"。

**修复建议**：解析失败时 `alert('COM 口格式错误')` 并 return；或允许纯数字。

---

### [P1-4] 通讯拓扑"修改"只改端口/地址，网关 ID 丢失

**位置**：`demo/project-detail.html:1232-1236`

**问题**：修改通讯配置时只传 `rs485_address` 和 `gateway_port`，没有 `gateway_id`。如果原设备已有网关但需切换端口，OK；但**拓扑图按 `gwNo` 分组**，若用户在"GW-001 的 COM1"下点修改并改成 `COM2`，下次加载时若存在多网关会分组混乱。

**修复建议**：修改对话框应允许同时选择目标网关；或至少明确只能改本网关下的端口与地址，禁止跨网关。

---

### [P2-1] 项目列表 API 默认 limit=100（潜在数据截断）

**位置**：`backend/app/api/projects.py:80`、`devices.py:55`、`gateways.py:33` 等

**问题**：默认 `limit=100`。前端调用 `api.projects.getProjects()` / `api.devices.getDevices()` 均未显式传入更大 limit。当：
- 服务器项目数 > 100 → `gateway-inventory.html` 的项目名称映射、搜索框都丢数据
- 单项目设备数 > 100 → `device-register.html`、`communication-setup.html`、`project-detail.html` 都只显示前 100 台

**现状**：本地库最大项目 33 台设备，共 3 个项目，暂无影响。但用户已部署到阿里云，实际数据规模未知。

**修复建议**：
- 前端关键列表调用统一传 `limit: 10000`（对网关库存/设备列表等全量需求）。
- 或后端把 `limit` 改为可选，传 null 则不分页。

---

### [P2-2] `deleteDevice` 子设备删除未 await

**位置**：`demo/device-register.html:1857`

**问题**：
```js
childIds.forEach(cid => { try { api.devices.deleteDevice(cid); } catch(e){} });
```
`deleteDevice` 是 Promise，`try/catch` 不能捕获未 await 的 rejection。会导致：
- 部分子设备后端删除失败时，无任何提示
- 下次页面加载时子设备"复活"

**修复建议**：改为 `await Promise.all(childIds.map(cid => api.devices.deleteDevice(cid).catch(e => console.warn(e))))`。

---

### [P2-3] `copyDevice` API 失败时本地复制，引入本地 ID（`Date.now()`）

**位置**：`demo/device-register.html:1825-1837`

**问题**：API 复制失败时，前端用 `Date.now() + i` 生成本地 ID 并塞入 `devices`。后续同步时，这些设备在其他电脑上不存在，同样是同步 bug。

**修复建议**：API 失败直接 `showError` 并中断，不再写本地。

---

### [P2-4] 拓扑图 `innerHTML` 拼接用户数据（XSS 隐患）

**位置**：`demo/project-detail.html:1172-1182`、`demo/gateway-inventory.html:386-391`

**问题**：`d.device_no`、`d.brand`、`d.model`、`roomName`、`typeName`、项目名等直接拼进 `innerHTML`，未转义。正常工况下数据都是系统生成的编号/受控字段，但若用户在"品牌/型号/项目名/冷库名"中输入 `<script>` 能触发 XSS。

**现状**：低风险（内部系统、有鉴权），但规范上应修。

**修复建议**：参考 `api.js._escapeHtml`，对所有用户输入字段统一转义。

---

### [P2-5] 网关库存搜索框 onclick 传数字 ID，失败安全

**位置**：`demo/gateway-inventory.html:388`

```html
onclick="pickAllocateProject(' + p.id + ')"
```
若 `p.id` 包含非数字或点击时 HTML 转义被破坏，会导致整个按钮失效。当前后端 `id` 都是整数，风险低，但建议改 `data-id` + 事件委托。

---

### [P3-1] `_generate_device_no_for_copy` O(N²) 查询

**位置**：`backend/app/api/projects.py:419-421`

**问题**：每次生成编号都做 `count()` 查询。对 1000 台设备的项目，复制会做 1000 次 count。可以改为：先取一次 count，在循环中自增。

---

### [P3-2] SQLAlchemy Pydantic `model_` 命名冲突警告

**现象**：启动和运行时一直出现 `UserWarning: Field "model_name" has conflict with protected namespace "model_"`。

**影响**：不影响功能，仅污染日志。

**修复建议**：在相关 schema class 中添加 `model_config = {"protected_namespaces": ()}`。
